How it should be done

A factual side-by-side of the original app (app/) and the rebuild (rebuild/). Both use Python, Streamlit and SQLite and follow the same analysis and design. Line counts were measured with wc -l; test counts by running each suite.

What a strong developer does differently

  1. Pass the database in, don't reach for it. Repository functions take a connection, so tests use a temporary file and one transaction can cover several steps. Original: app/pawmatch_auth.py (get_connection, used by every module). Rebuild: rebuild/pawmatch/db.py (connect) and rebuild/tests/conftest.py.
  2. Check permissions where the action happens. The page hides the button, and the function refuses anyway. Original: app/pages/7_Admin_Dashboard.py lines 41-45. Rebuild: rebuild/pawmatch/services.py and rebuild/tests/test_admin_access.py.
  3. Write the rule once, then test its edges. Each form has one validator returning errors by field, tested with normal, boundary and wrong data. Original: app/pawmatch_auth.py, app/pawmatch_animals.py, app/pawmatch_matching.py. Rebuild: rebuild/pawmatch/validation.py and rebuild/tests/test_validation.py (48 cases).
  4. Define the algorithm so it can't be misread. The normalisation (÷ 72), the partial activity credit, the warning factors and the tie-break order are written at the top of the module and each has a test. Original: app/pawmatch_matching.py. Rebuild: rebuild/pawmatch/matching.py and rebuild/tests/test_matching.py.
  5. Keep pages thin. A page reads input, calls one service and draws the result. Original: app/pages/7_Admin_Dashboard.py (567 lines). Rebuild: rebuild/webui/views/admin.py (110 lines).
  6. Let the theme do the styling. Colours come from one theme file instead of custom CSS. Original: app/pawmatch_style.py (2,256 lines). Rebuild: rebuild/.streamlit/config.toml (15 lines).
  7. Back validation with the database. CHECK and UNIQUE constraints repeat the rules, so bad data can't arrive by another route. Original: app/pawmatch_animals.py (CHECKs on animals). Rebuild: rebuild/pawmatch/db.py (CHECKs on all four tables) and the constraints test in rebuild/tests/test_repository.py.
  8. Test the pages too. Streamlit's AppTest runs pages headless, so "adopters can't open the staff page" is checked automatically, not by hand. Original: app/tests/ (no page tests). Rebuild: rebuild/tests/test_ui_smoke.py.

Where the original is ahead: it tracks an animal's status (Available, Reserved, Adopted) and stores extra fields such as other pets and experience on each animal, which the rebuild does not.
