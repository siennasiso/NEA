Database structure


Tables                                    Purpose

Users                                     Stores registered user and
                                          administrator account details

Animals                                   Stores user profiles, care needs and
                                          matching requirements

Questionnaire responses                   Stores answers submitted by users

Matchresults                              Stores calculated compatibility scores
                                          between responses and animals


One user can complete multiple questionnaire responses, each questionnaire
can produce multiple compatibility results because it is compared to every
available animal. Each animal can therefore appear in multiple match results
belonging to different users or questionnaire attempts.
   -​ Users 1 → Many Questionnaire responses
   -​ Questionnaire responses 1 → Many matchresults
   -​ animals 1 → Many matchresults


Validation
All user entered data should be validated before it is processed or stored in the
SQLite database. Streamlit controls such as dropdowns radio buttons and
number inputs will restrict the range of values users can enter. However, the
backend will still validate the submitted values because interface controls alone
should not be relied on.

        Validation
            1.​ Name
            -​ Presence check: Field cannot be empty or contain only spaces
            -​ Length check: name must be between 2 and 50 characters
            -​ Whitespace check: spaces at beginning and end will be removed


            2.​ Email address
            -​ Presence check: Field cannot be empty or contain only spaces
            -​ Format check: value must contain a @ and domain
            -​ Uniqueness check: a database query will check the address not already registered
            -​ Whitespace check: spaces at beginning and end will be removed
            -​ Check characters: convert all to lower case


            3.​ Age
   -​ Presence check: Field cannot be empty or contain only spaces
   -​ Type check: data must be a whole number
   -​ Range check: age must be 18+


   4.​ Password
   -​ Presence check: Field cannot be empty or contain only spaces
   -​ Length check: password must be more than 8 characters
Registration
   -​ Confirmation check: the confirmation field must exactly match original password
   -​ Security processing: the valid password will be hashed before it is inserted into the
        database and the original password will never be stored.
Login
   -​ The password will be checked against the stored password hash rather than compared
        as plain text.


Registration outcome
   -​ The account will be created if every field passes validation, individual messages will be
        shown if one or more fields are invalid.


Session check
   -​ A session will only be created after successful authentication. Invalid information will
        leave users on the login page and will not allow them to access the user or admin page.

Validation

  1.​ Animal name
  -​ Presence check: Cannot be empty
  -​ Length check: Between 1 and 50 characters
  -​ Format check: Letters, spaces, apostrophes, hyphens and appropriate numbers may be
      allowed
  2.​ Species
  -​ Presence check: Must be selected.
  -​ Lookup check: Must be Dog, Cat or Rabbit.
  -​ A drop-down menu will restrict the choices.
  3.​ Breed
  -​ Presence check: Cannot be empty
  -​ Length check: For example, between 2 and 50 characters
  -​ Format check: Must not consist entirely of unsupported symbols
  4.​Age
  -​ Presence check: Must be provided
  -​ Type check: Must be a whole number
  -​ Range check: Cannot be negative and must be within the designed maximum animal
     age
  5.​Sex
  -​ Lookup check: Must be Male, Female or Unknown
  -​ A drop-down menu prevents invalid values
  6.​Size
  -​ Lookup check: Must be Small, Medium or Large

  7.​Personality
  -​ Presence check: A description must be provided
  -​ Length check: For example, between 20 and 1,000 characters
  -​ Whitespace check: A value consisting only of spaces will be rejected

  8.​Exercise need
  -​ Presence check: An option must be selected
  -​ Range check: Must be between 1 and 3
   9.​Minimum housing requirement
   -​ Presence check: Must be selected
   -​ Range check: Must be between 1 and 3

   10.​ Maximum hours alone
   -​ Type check: Must be an integer
   -​ Range check: Must be between 0 and 24

   11.​ Garden required
   -​ Type check: Must be stored as a Boolean value 0 or 1
   12.​Child compatibility
   -​ Type check: Must be stored as a Boolean value 0 or 1
   13.​Medical notes
   -​ This field may be optional
   -​ Type check: it will have a maximum length
   -​ Text will be stored as plain text rather than interpreted as code
   14.​Animal image
   -​ Presence check : An image must be uploaded if every profile requires one
   -​ File-type check : Only approved formats such as JPG, JPEG and PNG will be accepted
   -​ File-size check : The file must not exceed the chosen maximum size
   -​ Filename handling : A safe, unique filename will be generated to avoid overwriting
       existing images

The animal record will only be inserted after all required fields pass validation. The SQL
statement will be parameterised and committed only after successful validation. A success
message will then confirm that the record has been created.

   -​ Preferred activity level / time available for exercise and care
   -​ Hours the animal would be left alone

   -​ Preferred animal size

   -​ Submit


Where it links
   -​ Amount of living space → minimum housing level
   -​ Garden access → garden required
   -​ Children in the home → child compatible
   -​ Preferred activity level → exercise need
   -​ Hours left alone → maximum hours left alone
   -​ Preferred species → animal species
   -​ Preferred size → animal size

However, these weights will not add to the compatibility percentage as their preferences do
not reflect animal suitability. It will influence the order in which suitable animals are displayed.

percentage as it matches the users preferences, but still ensuring preferred animals are
presented as users top choices as this will make them more inclined to adopt. If the user picks
‘no preference’ no animal will receive a bonus.
